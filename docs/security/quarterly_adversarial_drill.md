# 季度对抗演练手册（IDA/动态调试/抓包）

## 目标
- 验证 E2EE、传输层与终端硬化在真实攻防中的有效性。
- 将“发现问题 -> 修复 -> 回归”固化为季度节奏。

## 频率与节奏
- 每季度 1 次完整演练（建议每季度第 2 个月执行）。
- 每次演练产出整改清单，并在 30 天内闭环。

## 场景清单
1. 静态逆向（IDA Pro）
- 提取关键路径：登录、密钥派生、消息收发、信任确认。
- 检查发布物是否符合 `strip/符号隐藏/混淆` 预期。

2. 动态调试器对抗
- 使用 x64dbg/Frida/自定义注入进行断点、Hook、返回值篡改。
- 验证 fail-close、TamperMode、敏感状态清理是否按预期触发。

3. 抓包与流量关联
- 抓取 TLS/KCP 链路，确认明文泄露面与元数据暴露面。
- 验证降级策略（如 KCP 非安全开关）是否被流程限制。

## 通过标准（最小）
- 未出现明文业务载荷泄露。
- 未出现“默认配置可降级到弱链路”。
- 反调试命中后存在可验证阻断或降权行为。
- 首次 Pin 信任记录具备双人复核审计证据。

## 产物要求
- `attack_notes.md`：步骤、工具、截图、命令。
- `findings.csv`：风险级别、影响面、复现方式、责任人、截止日期。
- `fix_verification.md`：修复提交与回归结果（含测试命令）。

## 整改 SLA
- P0：72 小时内给出缓解，7 天内修复。
- P1：14 天内修复。
- P2：纳入下一迭代。
